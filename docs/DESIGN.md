# 设计约束与实现规范

本文档汇总仓库级的实现与文档约定，用于减少重复读取长说明。

## 文档约定

- 新增或修改 Markdown 文档时，默认使用中文描述。
- 入口文档只保留索引和规则，不堆积大段背景。
- 设计稿、执行稿和专题方案优先放在 `docs/plans/`。
- 任务中间产物、长日志和分析摘要不要写进正式设计文档，优先放到 `.workspace/`。
- `docs/plans/` 文档必须区分“当前实现基线”“候选方案”“工作流说明”“历史方案”，不要让所有文档都看起来像当前主路径。
- 涉及当前实现基线的代码改动时，应同步更新对应文档，或至少把原文档标记为“已偏离实现”。
- 新的主路径若替代旧方案，应在新旧文档中都写清楚替代关系。

## Unity / C# 约定

- 使用 4 空格缩进，文本编码为 UTF-8。
- 类型、方法、属性使用 `PascalCase`。
- 局部变量和参数使用 `camelCase`。
- 私有序列化字段使用 `_camelCase`。
- 优先保持 `MonoBehaviour` 小而单一职责。

## 渲染模块约定

- 每个渲染功能保持独立目录。
- `ScriptableRendererFeature` 与 Pass 分职责组织。
- 渲染逻辑尽量集中在 URP `ScriptableRendererFeature` / Pass。
- 不做与当前问题无关的渲染重构。

## 资源与项目文件约定

- `Assets/` 目录落位以 `docs/assets-directory-layout.md` 为准。
- 新增项目资源优先进入 `Assets/Project/`，二级目录按资源类型划分。
- 外部资源包优先进入 `Assets/ThirdParty/`，除非 Unity 包或现有工具链对根级路径有硬依赖。
- 不要无意义修改 `.meta` 文件。
- 不要顺手保存无关场景、预制体或项目设置。
- `Library/`、`Temp/`、`Logs/`、`obj/`、`.workspace/` 默认不作为功能源码评审对象。

## 验证约定

- 修改完成后运行最小必要验证。
- 如果没有执行验证，必须明确说明原因和剩余风险。
- 常用验证命令仍以根级 `AGENTS.md` 为准。
